# Robinʼs Photos

Photo album site at [photos.robinclowers.com](https://photos.robinclowers.com).
A TanStack Start app on Cloudflare Workers with a D1 (SQLite) database, ported
from the original Rails app in `~/src/photo-album`.

Images are served from the public S3 bucket `robin-photos`, laid out as
`<album-slug>/<size>/<filename>` where `size` is one of `original`,
`mobile_sm`, `tablet`, or `desktop`.

## Stack

- TanStack Start + Router (file-based routes in `src/routes`)
- React 19, MUI v7 with Pigment CSS, Tailwind v4 for layout utilities
- Drizzle ORM over Cloudflare D1 (`src/db`)
- Cloudflare Workers via `@cloudflare/vite-plugin` and wrangler
- Biome for lint/format, Vitest for tests, lefthook for pre-commit hooks

Conventions for contributors and agents live in [AGENTS.md](./AGENTS.md).

## Development

```bash
bun install
bun run dev          # http://localhost:3000, workerd + a local D1 copy in .wrangler/state
bun run test         # vitest
bun run check        # biome lint + format check
bun run typecheck    # tsc --noEmit
```

Local secrets go in `.dev.vars` (gitignored). Copy `.dev.vars.example` and
fill in the values. Non-secret configuration lives in `wrangler.jsonc` under
`vars`.

## Environments

| | production | staging |
|---|---|---|
| Worker | `photo-album-tanstack` at photos.robinclowers.com | `photo-album-tanstack-staging` on workers.dev |
| D1 | `photo-album` | `photo-album-staging` (seeded from a production export) |
| Deploy | `bun run deploy` | `bun run deploy:staging` |
| Secrets | `wrangler secret put NAME` | `wrangler secret put NAME --env staging` |

Named environments do not inherit bindings, so any new binding or var added
to the top level of `wrangler.jsonc` must also be added under `env.staging`.

## Database

The schema is in `src/db/schema.ts`; migrations are generated by drizzle-kit
into `drizzle/` and applied with wrangler.

```bash
bun run db:generate            # create a migration from schema changes
bun run db:migrate:staging     # apply to staging
bun run db:migrate             # apply to production
```

All existing databases (production, staging, local) were seeded from SQL
dumps rather than by running migration `0000`, so wrangler has no record of
it. Before the first `migrations apply` against such a database, record the
baseline once so wrangler does not try to re-create the tables:

```sql
CREATE TABLE IF NOT EXISTS d1_migrations(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT UNIQUE,
  applied_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
INSERT OR IGNORE INTO d1_migrations(name) VALUES ('0000_careful_paladin.sql');
```

Run it with `bunx wrangler d1 execute <db> [--remote|--local] --command "..."`.
Staging and local already have this; production still needs it.

To refresh staging from production:

```bash
bunx wrangler d1 export photo-album --remote --output tmp/prod-d1-export.sql
bunx wrangler d1 execute photo-album-staging --remote --yes --file tmp/prod-d1-export.sql
```

`scripts/convert-pg-to-sqlite.js` is the one-off converter used to move the
original Postgres dump into D1 and is kept for reference.

## Deploying

```bash
bun run deploy:staging   # build + wrangler deploy --env staging
bun run deploy           # build + wrangler deploy (production)
```

`bun run cf-typegen` regenerates `worker-configuration.d.ts` after changing
bindings in `wrangler.jsonc`.
